# linux服务器管理

在 Mac 上通过界面连接、部署和维护 Linux 服务器，当前版本为 **v0.3.13**。桌面包适用于 **macOS 11 或更新版本 / Intel 与 Apple Silicon（universal2）**，不提供 Windows 包。

## 下载与更新

从 [GitHub Releases](https://github.com/yushengsheng/linux-manager/releases/latest) 下载 `linux-server-manager-macOS-universal2-v0.3.13.zip`，使用同页 `SHA256SUMS` 或同名 `.sha256` 核对。解压后正常退出旧程序，将主程序和启动器保留在同一文件夹，双击 `启动linux服务器管理.app`。

安装包自带 Python / Tk 和依赖，无需开发环境，可整组移动目录或复制到其他 Mac。登录档案与客户端设置分别属于每台 Mac，新电脑需要自己的连接资料。日常本地使用根目录 `启动本地最新版.app` 直接加载源码；只有用户明确要求发版时才打包。

先正常退出旧程序再打开新版。沿用原本机档案、私钥及钥匙串，不需要重新添加服务器；新版可能需要再次允许访问钥匙串。本包使用临时签名，未经过 Apple 开发者公证：确认下载来源和校验值后，如系统拦截，按 macOS「隐私与安全性」的提示允许打开，不要关闭系统安全检查。

更新说明见 [v0.3.13 发布说明](RELEASE_NOTES.md)。

## 功能

v0.3.13 支持读取与管理其他方式安装的项目，项目列表和基础信息可在重启后恢复；改进独立滚动、钥匙串授权和只读查询开销。保留 Linux 直接下载及校验、“停止等待”、独立 REALITY、节点二维码与证书兼容功能。详细验证范围见[测试记录](linux服务器管理测试记录.md)。

- 左侧保存多台服务器与多账号档案；点击即可使用保存的登录信息连接，可用连接直接复用。
- 单机工作区：概览、应用管理、账号、安全与操作记录；全部既有功能保留。
- SSH 持续连接与短暂断线自动重连，执行任务时阻止服务器切换，避免操作错机器。
- 管理当前服务器 → 命令行：复用已有 SSH 连接打开 macOS 系统终端，可连续输入、粘贴多行代码及使用 top、vim；使用当前登录账号，输入 exit 退出。
- 提交前保存固定任务编号，响应丢失先查回执；远端原子去重，新连接有界重试，确认结果可查回，不重跑已完成安全步骤。
- 账号创建、改名、密码和加密密钥管理、登录方式设置及一键安全方案。
- 所有新密码设置入口可一键生成 40 字符强随机密码，新私钥口令为 48 字符；确认密码同步填写。普通账号新密码提交前保存并回读本机钥匙串副本，可从操作记录离线查看。
- 自动安全更新同时核验生效配置和实际 APT 定时调度；不立即补跑升级、不自动重启，失败恢复原配置与定时器状态。
- 小军交易系统、Hysteria2、独立 VLESS + REALITY + Vision、3x-ui 代理面板及 Nginx 的安装、配置调整和版本切换。
- 独立 VLESS 仅填写 TCP 端口，自动生成连接凭据，无需面板、自有域名或证书；与 HY2 可共存。部署后复制单节点链接导入客户端。
- HY2 / VLESS 链接旁提供二维码图标，点击即可扫码导入；二维码只在本机生成。
- 小军交易查询 GitHub API 受限时，自动使用官方公开发行页面和下载链接；无需 GitHub 登录，仍核对具体版本及 SHA-256。
- 部署前显示变化：条件一致无需重复安装，配置变化按需调整，升级降级先备份，失败恢复原项目。
- 服务维护、配置备份恢复、访问网址、端口、节点和订阅信息、运行日志及操作记录。Nginx 核心管理与交易专属入口分离，部署回滚失败可按原任务再次恢复并核验服务状态。
- 项目卸载：移除本程序安装的程序和专属服务，默认保留配置、账号、账本及证书；未知或共享布局拒绝自动卸载。Nginx 仅移除本程序独立站点，不删除共享核心。移除文件保留管理员恢复备份，仍占磁盘。
- 配置页、部署确认及项目信息明确标注 TCP / UDP；HY2 节点仅 UDP，面板节点按实际配置标注 TCP、UDP 或两者，证书验证 TCP 80 单独提示。
- 各功能提供可点击的大白话说明。

登录档案、SSH 私钥、口令及本机管理记录只保存在本机，不启用云同步或遥测。口令保存在 macOS 本机钥匙串。部署只向所选服务器发送运行必需的配置和公钥；软件包由 Linux 直接从官方来源下载，私钥不会传到服务器。

详细用法见 [使用说明](linux服务器管理使用说明.md)，验证结果见 [测试记录](linux服务器管理测试记录.md)。自动部署支持 Ubuntu 24.04、Debian 12/13；交易系统支持 x86_64。云平台安全组需自行放行对应端口。

## CLIProxyAPI

新增 CLIProxyAPI v8 安装、HTTPS 后台、独立管理／客户端 Key、每 30 分钟稳定版更新、每日备份及失败恢复。安装和更新保留现有上游授权、Key 与配置；授权期间不提交维护任务或自动更新核心。

登录请从「应用管理 → 运行与备份」选择 CLIProxyAPI：直接登录 Codex／Antigravity，或在下拉框选择 Claude、Devin、Kimi 国内／国际、xAI、Muse (Meta)。macOS 按应用标识定位 Google Chrome，支持个人应用目录和移动后的安装位置；普通打开授权页无需控制 Chrome 的自动化权限，失败时使用系统默认浏览器。回调自动经已信任 SSH 转交服务器，不用复制网址或本机 Token。设备授权无需回调端口，端口占用不抢占。Vertex JSON、API Key 与插件仍使用官方后台。

授权失败或取消会释放本机接收器和界面；服务器暂时不可达时保留原始错误，再次登录先按原会话编号重试清理。服务器已结束或过期的会话可重复取消，临时文件／专属端口保护规则清理失败会在下次登录重试；其他电脑尚在进行的授权不会被取消。关闭旧网页后重新发起登录。

Codex、Antigravity 已在测试服务器实际保存并识别授权，其余方式的验证范围见[测试记录](linux服务器管理测试记录.md)。一般只授权一次，核心更新不删除授权；账号撤销、凭据失效或上游改变协议仍可能要求重新登录，不能保证永久兼容未知新版本。

在同一页面的「本机客户端 · 配置与恢复」可一键配置 GPT / Codex、Claude Code、Pi、OpenCode。自动读取所选服务器当前有效客户端 Key，通过本机 HTTPS 验证模型目录，选择默认模型后先备份再写入本机配置和可选模型列表；GPT 可在 App 模型下拉框切换，Pi 可在 `/model` 切换，OpenCode 使用 `/models`。不安装客户端、不修改服务器或上游账号。Claude 入口适用于 Claude Code 命令行。配置后完全退出并重开客户端，新建会话验证；服务器增加模型后再次一键配置以刷新列表。

点击「选择已安装应用」，从图标列表选择这台 Mac 的 GPT / Codex 或 OpenCode；程序按应用标识自动定位当前用户的配置，不需要选择路径。支持系统／个人应用程序目录、一层分组及通过 macOS 元数据识别移动过的应用；应用安装位置与配置目录互相独立。保留已知环境变量和历史自定义目录记录。Claude Code、Pi 命令行版直接使用原有一键配置按钮，程序自动定位；Claude 桌面聊天应用不会误识别为 Claude Code。

「恢复原客户端配置」按客户端选择首次配置前或任意历史版本；恢复前另存当前配置，失败自动撤回。备份仅存本机管理器数据目录的 `client-config-backups`，可在服务器离线时恢复；恢复会覆盖相关配置文件中的后续设置，原本不存在的文件会删除。具体路径及配置兼容限制见[使用说明](linux服务器管理使用说明.md)。

日常使用 `启动本地最新版.app` 加载当前源码，沿用本机档案和钥匙串。

## 本地运行和测试

「应用管理 → 运行与备份 → 刷新读取全部项目」一次刷新内置项目与其他已安装项目，直接合并到「要管理的项目」下拉列表，在当前页面展示详情和管理按钮。轻量只读检查自建 systemd 系统服务、已连接的用户服务、Docker、PM2 已保存应用、监听中的独立程序和常用安装目录，包括 Hermes 常见隐藏安装目录；未发现的目录可手动登记。外部服务和容器支持各自能力范围内的启停、重启，systemd 可管理自启，执行前确认并重新核对目标；独立进程和目录只读，不支持的按钮禁用。原有六类项目保持原功能。系统组件不作为业务项目管理；扫描不会启动用户服务管理器。

读取结果按服务器保存在本机，下次启动直接恢复项目下拉列表和基础信息，切换项目不会自动重扫；点击刷新才更新。服务器概览的「项目与配套服务」同步显示这些项目，可直接打开对应管理选项，运行项目统计包含已识别的外部项目。保存结果标注保存时间，运行状态以最近一次读取为准。缓存文件仅本机用户可读写，使用字段白名单，不包含密码、令牌、环境变量或业务日志；登录凭据仍保存在钥匙串。

通用识别按部署方式关联服务、容器、PM2、进程与监听端口，提取公开版本号或安装修订；对已归属项目的 TCP 端口使用限时、限量的本机 HTTP HEAD 检查，并关联 Nginx 反向代理的域名、端口和路径，展示网页入口及识别依据。检查不读取网页正文、不发送凭据、不跟随外部跳转、不开放端口、不启动服务。仅本机监听的网页会单独说明。没有网页服务或暂未确认协议时说明原因，不将任意端口猜为访问网址。

外部项目手工补充的账号、密码、管理网址和备注仅存本机钥匙串；此入口不修改服务器账号密码，实际改密从项目原后台进行。扫描仅提取版本和代理入口元数据，不导出完整配置、环境变量、业务日志或数据库，不执行项目代码，不递归遍历磁盘。未运行、没有服务记录且位于非常用目录的项目需手动登记；特殊部署与账号机制仍需专门适配。

本机凭据集中存入同一条不参与同步的钥匙串记录，启动时共享一次读取，取消预读各项目凭据。旧版逐条记录在首次使用时迁移，迁移经过回读验证且保留原记录；首次迁移仍可能遇到系统对旧记录的授权提示。之后正常启动无需逐项授权。删除登录信息时，集中记录设为空并删除对应旧记录，防止旧密码再次出现。凭据不写入普通文件。

开发期间直接双击项目根目录的 `启动本地最新版.app`。它自动寻找本机可用的 Python 3.11 或更新版本（需要 Tk 和 segno），支持项目虚拟环境、uv、Homebrew 和 Python.org 安装；可用 `LINUX_MANAGER_PYTHON` 指定运行环境，不绑定用户名或 CPU 架构。它直接读取同目录最新源码，无终端窗口；沿用原桌面版档案、加密私钥和本机钥匙串。正常退出旧程序后再打开，修改代码后重启即可，不需要重新打包。只有用户明确要求发版、生成正式安装包或分发产物时才执行打包；测试通过不代表发版授权。

此入口依赖这台 Mac 的源码目录及运行环境，不能单独分发给其他电脑。旧交付文件已清理；需要分发时，在用户明确要求发版后生成新的独立通用包。

本次的占用、依赖、运行开销与保留项分析见[项目轻量化检查](项目轻量化检查.md)。

发版前的完整检查、修复及验证边界见[发版前检查](发版前检查.md)。

使用安装了 Tk 的 Python 3.11 或更新版本（当前完整回归使用 Python 3.13 / Tk 8.6）：

```sh
python3 -m pip install -r requirements.txt
python3 linux服务器管理.py --desktop-data
python3 tools/run_tests.py
```

非 macOS 环境不提供本机钥匙串保存功能。真实服务器测试工具需要使用者自行准备本机测试档案，不会从仓库获取任何登录资料。

## 构建 macOS 程序

```sh
python3 tools/build_desktop.py
```

构建工具使用隔离环境及固定的打包依赖，输出到 `/private/tmp/linux-manager-build/dist/`。生成的 `linux服务器管理.app` 可直接双击打开；原生程序元数据同步源码版本，构建后重新签名并核验。本版 Mac 包使用 universal2 构建，已在 Apple Silicon 上完成 arm64 原生与 x86_64（Rosetta）验收；尚未在 Intel 实体机验证。

使用带 Intel／Apple Silicon 双架构的 universal2 Python 和 Tk，可执行 `python3 tools/build_desktop.py --target-arch universal2` 构建通用 Mac 包，输出到 `/private/tmp/linux-manager-build-universal2/dist/`。单架构运行环境会在构建前明确拒绝通用包，避免把 arm64 包误标为兼容 Intel。此入口不发布到 GitHub。

如需同文件夹的无终端启动器，在 macOS 中执行：

```sh
osacompile -o 启动linux服务器管理.app scripts/启动linux服务器管理.applescript
```

把启动器与主程序放在同一文件夹。仓库不包含本机登录资料、私钥、运行数据或历史安装包。

通用主程序构建完成并整理好交付目录后，执行 `python3 tools/package_desktop.py` 生成标准 UTF-8 ZIP 和 SHA-256，保留执行权限及框架链接。

本地安装包验收：`python3 tools/final_release_audit.py`。此工具不读取用户连接档案、不访问真实服务器，会核对当前源码摘要、签名、双架构环境自检、ZIP 内容及 SHA-256。`tools/publish_desktop.py` 是依赖旧开发窗口状态的本机替换工具，不作为当前通用包的打包或发版入口。
